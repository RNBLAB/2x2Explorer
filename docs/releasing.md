# 판 올리기와 패치노트

버전 번호를 언제 올리는지, 패치노트를 어떻게 쓰는지, 내보낼 때 무엇을 하는지를 적어 둔 문서입니다.

## 1. 번호는 세 자리이고 각 자리에 조건이 있습니다

`MAJOR.MINOR.PATCH` — 예: `1.2.3`

판단 기준은 하나입니다. **새 판으로 덮어쓰고 그냥 켰을 때, 쓰던 사람이 어제와 똑같이 쓸 수 있는가.**

| 자리 | 올리는 때 | 보기 |
|---|---|---|
| MAJOR | 쓰던 사람이 뭔가를 다시 해야 할 때 | 설정을 자동으로 못 옮김 · 지원하는 윈도우 판을 올림 · .NET 판을 올려 사용자가 런타임을 새로 깔아야 함 · 있던 기능을 뺌 |
| MINOR | 기능이 늘었고 사용자가 할 일은 없을 때 | 일괄 이름 바꾸기 추가 · 미리보기 형식 추가 · 설정 항목 추가(기본값으로 채워짐) |
| PATCH | 고치기만 했을 때 | 버그 수정 · 속도 개선 · 글자·번역 수정 |

**크기는 기준이 아닙니다.** 일괄 이름 바꾸기처럼 창 세 개가 딸린 큰 작업이라도, 쓰던 사람이 할 일이 없으면 MINOR 입니다.

**MAJOR 를 이정표로 쓰지 않습니다.** 큰 작업을 했다고 2.0 을 붙이지 않습니다. 그렇게 하기 시작하면 번호가 "올려도 되나"를 알려 주지 못하고 기분을 알려 주게 됩니다. 1.x 가 몇 년 가는 것은 정상이고, 호환을 지켰다는 뜻입니다.

## 2. 설정 파일 판 번호는 따로 셉니다

`settings.json` 의 `version` 은 프로그램 버전과 다른 번호입니다. 설정 구조가 바뀔 때만 올립니다.

- 옮기는 코드가 있어서 예전 설정이 그대로 살아나면 → 프로그램은 MINOR
- 옮길 수 없어서 기본값으로 떨어지면 → 프로그램은 MAJOR

## 3. 버전을 고치는 자리는 한 곳입니다

`Directory.Build.props` 의 `<Version>` 입니다. 세 프로젝트가 모두 이 값을 받습니다. 다른 곳에 버전을 적지 않습니다.

## 4. 패치노트는 `CHANGELOG.md` 가 원본입니다

저장소 뿌리의 `CHANGELOG.md` 에 먼저 쓰고, 내보낼 때 그 판의 구역을 그대로 GitHub Release 설명에 옮깁니다. 두 곳에 따로 쓰지 않습니다.

형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/) 를 따릅니다. 맨 위에 `## [Unreleased]` 구역을 두고, 무언가 고칠 때마다 거기에 한 줄씩 쌓습니다. 내보내는 날 그 제목을 `## [1.2.0] - 2026-10-01` 로 바꾸고 위에 빈 `## [Unreleased]` 를 새로 답니다.

한 판 안의 소제목은 이 여섯 가지만 씁니다. 해당 없는 것은 적지 않습니다.

- **추가** — 새로 생긴 것
- **변경** — 하던 일이 달라진 것
- **사라질 예정** — 다음 판에서 뺄 것을 미리 알림
- **사라짐** — 이번에 뺀 것
- **고침** — 버그 수정
- **보안** — 보안과 관련된 수정

## 5. 문장은 쓰는 사람이 겪는 변화로 씁니다

커밋 메시지를 붙여 넣지 않습니다. 커밋은 코드를 고친 기록이고 패치노트는 사용자가 무엇을 느끼는지의 기록이라 쓰임이 다릅니다.

- 나쁨: `PreviewHandlerHost 에 WS_CLIPCHILDREN 추가`
- 좋음: `한글 문서 미리보기가 빈 화면으로 뜨던 것을 고쳤습니다`

한 줄에 한 가지만 적습니다. 파일 이름이나 클래스 이름은 필요할 때만 씁니다. 안에서만 고친 것(리팩터링, 주석, 빌드 설정)은 사용자가 겪는 변화가 없으므로 적지 않습니다.

## 6. 내보내는 차례

1. `start.cmd` 로 빌드해 이번 판에서 고친 것을 한 번씩 눌러 봅니다
2. `Directory.Build.props` 의 `<Version>` 을 올립니다
3. `CHANGELOG.md` 의 `[Unreleased]` 를 판 번호와 날짜로 바꾸고, 새 `[Unreleased]` 를 위에 답니다. 맨 아래 링크 줄도 같이 고칩니다
4. `pack.cmd` 를 돌립니다. 차례대로 다음을 하고, 하나라도 어긋나면 설치 파일을 만들지 않고 멈춥니다
   - `CHANGELOG.md` 에서 `## [<판>]` 구역을 떼어 `build\dist\2x2Explorer-<판>-notes.md` 로 씀(구역이 없거나 비었으면 멈춤, `[Unreleased]` 에 남은 줄이 있으면 경고)
   - `Explorer.Core` 시험(`build\test.log`, 실패하면 멈춤)
   - 자체 포함 publish → Inno Setup → `build\dist\2x2Explorer-<판>-setup.exe`
   - 설치 파일의 SHA-256 을 `build\dist\2x2Explorer-<판>-setup.exe.sha256` 에 씀
5. 커밋하고 태그를 붙입니다 — `git tag v1.2.0` · `git push --tags` (저장소가 있을 때)
6. GitHub 에서 Release 를 만들어 태그를 고르고, `…-notes.md` 내용을 설명에 붙이고, 설치 파일과 `.sha256` 을 올립니다

`pack.cmd` 는 아무것도 올리지 않습니다. 게시는 사람이 합니다(2026-09-27 사용자 결정). 다른 스크립트에서 부를 때는 `pack.cmd /nopause` 로 끝의 키 대기를 건너뜁니다.

떼어 내기와 해시는 `installer/release-files.ps1` 이 합니다. 이 파일은 ASCII 로만 씁니다 — Windows PowerShell 5.1 은 BOM 없는 스크립트를 옛 코드 페이지로 읽기 때문입니다.

## 7. 새 판을 설치하면 이전 판을 먼저 지웁니다

`installer/2x2Explorer.iss` 의 `[Code]` 가 설치 직전에 같은 `AppId` 로 깔린 이전 판을 찾아, 그 판의 제거 프로그램을 조용히 돌린 뒤 새 판을 설치합니다. 덮어쓰기만 하면 새 판에 없는 옛 파일이 설치 폴더에 남기 때문입니다. 1.1.0 부터입니다.

- 찾는 곳: 사용자 전용 설치(HKCU)와 모든 사용자 설치(HKLM) 제거 항목 둘 다. 다른 폴더에 깔린 이전 판도 지웁니다
- 남는 것: `%APPDATA%\2x2Explorer`(설정·이름 바꾸기 기록). 설치 폴더 위치, 사용자 전용/모든 사용자 선택, 바탕 화면 아이콘 선택도 마법사가 시작할 때 이전 판에서 읽어 오므로 이어집니다
- 지워지는 것: 이전 설치 폴더 안의 파일 전부(`debug.log` 포함)
- 프로그램이 켜져 있으면: 앱이 `2x2Explorer.Running` 뮤텍스를 쥐고 있고 `.iss` 의 `AppMutex` 가 그것을 봅니다. 설치를 시작할 때와 이전 판을 지우기 직전에 닫으라고 알립니다. 뮤텍스 이름을 바꾸면 `src/Explorer.App/Services/RunningMarker.cs` 와 `.iss` 를 함께 고칩니다
- 제거가 실패하면: 설치를 멈추고 까닭을 알립니다. 모든 사용자 설치를 지울 때 나오는 관리자 권한 요청을 거절한 경우도 여기에 들어갑니다
- 설정 파일을 지우는 `[UninstallDelete]` 는 넣지 않습니다. 넣으면 판을 올릴 때마다 설정이 사라집니다

한계: 1.0.0 은 뮤텍스를 쥐지 않으므로, 1.0.0 이 켜진 채로 1.1.0 을 설치하면 켜져 있음을 미리 알아보지 못합니다. 그때는 설치 마법사의 `CloseApplications` 가 잠긴 파일을 보고 닫으라고 알립니다.

설치 마법사의 한국어 문구 가운데 `[Code]` 에서 쓰는 것은 `installer/Korean.custom.isl` 에 있습니다. `.iss` 를 ASCII 로 두기 위해서입니다.

## 8. 하지 않기로 한 것

- 릴리즈 후보(`1.0.0-rc.1`) 같은 앞붙임 판은 쓰지 않습니다. 혼자 만드는 프로그램이라 단계를 나눌 이유가 없습니다
- 판마다 마이그레이션 안내문을 따로 쓰지 않습니다. MAJOR 를 올릴 때만 `CHANGELOG.md` 의 그 구역 맨 위에 "이 판으로 올리면 …를 다시 하셔야 합니다" 한 문단을 답니다
- 패치노트는 한국어로만 씁니다. 영어가 필요해지면 그때 구역을 나눕니다
