# 설계 결정

확정된 것만 적습니다. 바꾸려면 이 문서를 먼저 고칩니다.

## D1. 스택은 WPF(.NET 10)입니다

미리보기가 PDF·오피스·동영상까지 가려면 Win32 셸 미리보기 핸들러(COM)를 창에 얹어야 하고, WPF는 `HwndHost`로 이걸 직접 할 수 있습니다. WinUI 3는 같은 일이 훨씬 까다롭습니다.

대신 기본 외형이 낡아 보이므로 테마 리소스를 직접 둡니다(`Resources/Themes`). 나중에 WPF-UI 같은 라이브러리로 갈아탈 수 있게 색은 모두 리소스 키로만 참조합니다.

## D2. 레이아웃은 고정 2x2입니다

칸의 크기와 개수는 바뀌지 않습니다. 칸에 들어가는 역할만 설정이 정합니다.

크기 조절(GridSplitter)은 넣지 않았습니다. 나중에 필요하면 `MainWindow.xaml`의 Grid에 스플리터를 추가하는 것으로 끝납니다.

## D3. 미리보기는 마지막으로 클릭한 패널을 따라갑니다

`PreviewSettings.FollowActivePane`이 true일 때의 동작이고, 기본값입니다.

두 가지를 규칙으로 못 박습니다.

1. 미리보기 패널 자체를 클릭해도 소스 패널은 바뀌지 않습니다. `PaneHost.OnPreviewMouseDown`에서 미리보기 역할은 `Activated`를 내보내지 않습니다.
2. 선택이 바뀌고 `DebounceMs`(기본 200ms) 뒤에 파일을 읽습니다. 방향키로 목록을 훑을 때 파일을 매번 여는 것을 막습니다.

`FollowActivePane`을 false로 두면 `FixedSourcePaneIndex` 패널만 따라갑니다.

## D4. 파일 조작은 윈도우 셸에 맡깁니다

복사·이동·삭제·이름 바꾸기를 `IFileOperation`(COM)으로 호출합니다. 진행률 창, 충돌 대화상자, 휴지통, 되돌리기를 윈도우가 처리합니다.

드래그앤드롭도 같은 셸 규약(`IDataObject`)을 씁니다. 그래야 윈도우 기본 탐색기나 다른 프로그램과 그대로 주고받습니다.

## D5. 시작 방식은 패널마다 옵션으로 정합니다

`PaneSettings.StartupMode`가 `startPath`(기본)이면 시작 위치 하나만 열고, `restoreTabs`이면 지난 세션의 탭을 모두 복원합니다. 어느 쪽이든 `StartPath`는 따로 지정해 둡니다.

시작 위치가 사라졌으면 존재하는 상위 폴더까지 거슬러 올라갑니다(`PathHelper.ResolveExistingDirectory`). 이동식 디스크나 네트워크 드라이브를 시작 위치로 잡았을 때 이 경로를 탑니다.

## D6. 검색은 Everything SDK로 합니다

`Everything64.dll`을 P/Invoke로 부릅니다(`Everything_SetSearchW` → `Everything_QueryW` → 결과 읽기). 검색 결과는 새 탭으로 엽니다.

Everything이 설치돼 있지 않거나 서비스가 떠 있지 않은 경우가 반드시 생기므로, 실패하면 현재 폴더 아래를 직접 열거하는 검색으로 떨어집니다(`SearchSettings.FallbackToEnumerate`).

x64 전용입니다. `Everything64.dll`과 셸 COM 호출이 모두 64비트를 전제하므로 두 Windows 프로젝트에 `PlatformTarget=x64`를 박아 두었습니다.

## D7. 색 테마는 윈도우 설정을 따릅니다

`AppSettings.Theme`이 `System`(기본), `Light`, `Dark` 중 하나입니다. System이면 레지스트리의 `AppsUseLightTheme`을 읽고, 실행 중에 사용자가 윈도우 테마를 바꾸면 `SystemEvents.UserPreferenceChanged`로 따라갑니다.

팔레트는 `Resources/Themes/Dark.xaml`과 `Light.xaml` 두 벌입니다. 키 이름이 같아야 하고, 화면 쪽은 모두 `DynamicResource`로 참조합니다. 그래서 앱 리소스의 첫 사전만 바꾸면 창 전체가 따라옵니다.

## D8. 탭 색은 테마 색을 씁니다

한때 스무 가지 색을 탭마다 순서대로 입혔으나 되돌렸습니다. 선택된 탭은 패널 바탕색에 테마의 강조색 밑줄, 나머지는 비어 있습니다. 창 전체가 윈도우 테마 하나로 통일됩니다.

## D9. "내 PC"는 경로가 아니라 표시로 다룹니다

드라이브를 모아 보여 주는 자리는 디스크 위의 폴더가 아닙니다. 그래서 경로 문자열 대신 `::MyComputer`라는 표시를 쓰고, 열거할 때만 `DriveInfo.GetDrives()`로 바꿉니다. 주소 표시줄에는 "내 PC"로 보이고, 그대로 쳐도 열립니다.

드라이브 뿌리에서 위로 가면 여기로 옵니다. 여기서는 새 폴더를 만들 수 없고, 폴더 감시도 걸지 않습니다.

좌상단 패널의 기본 시작 위치입니다. 이미 바탕화면으로 저장돼 있던 설정은 판 3으로 올리면서 한 번만 바꿔 줍니다. 직접 고른 위치는 건드리지 않습니다.

## D10. 네 칸 모두 탐색기이고, 미리보기는 칸마다 붙습니다

미리보기 전용 패널을 없앴습니다. 패널마다 `PreviewViewModel`을 하나씩 갖고 자기 패널에서 고른 파일만 따라갑니다. 활성 패널을 찾아 신호를 돌리던 배선이 사라져 구조가 단순해졌습니다.

미리보기 폭은 A4 세로비율(210:297)로 높이에 맞춰 잡고, 패널 폭의 절반을 넘지 않게 제한합니다. 자기 높이를 XAML 바인딩으로 참조하면 배치가 한 박자 늦게 따라와 깜빡이므로 `SizeChanged`에서 계산합니다.

## D11. 즐겨찾기는 최대 10개, 시작할 때 탭으로 열립니다

창 위쪽 전체 메뉴에서 등록·삭제·열기를 합니다. 패널이 시작할 때 시작 위치 탭 다음에 즐겨찾기를 한 폴더씩 탭으로 엽니다. 지난 탭을 복원하는 모드에서는 복원한 탭이 자리를 차지하므로 건너뜁니다.

메뉴 항목은 코드에서 직접 만듭니다. WPF 스타일의 `Setter.Value`에는 Binding을 넣을 수 없어, `ItemsSource`로 만든 메뉴 항목에 명령을 걸 방법이 마땅치 않기 때문입니다.

## D12. 파일 조작은 전부 IFileOperation을 거칩니다

복사·이동·삭제·이름 바꾸기를 직접 구현하면 진행률 창, 같은 이름 충돌 처리, 휴지통, 되돌리기를 모두 만들어야 합니다. 셸에 맡기면 넷 다 딸려 옵니다.

COM 인터페이스는 선언 순서가 곧 함수 표의 순서입니다. 쓰지 않는 함수도 자리를 채워 두어야 하고, 중간에 끼워 넣거나 빼면 엉뚱한 함수가 불립니다.

클립보드도 윈도우 탐색기와 같은 규약을 씁니다. 파일 목록은 FileDrop, 복사인지 잘라내기인지는 "Preferred DropEffect"라는 4바이트 값입니다. 그래서 우리가 복사한 것을 탐색기에 붙여넣을 수 있고 그 반대도 됩니다.

## D13. 미리보기는 Ctrl+휠로 확대합니다

배율 1.0이 "너비 맞춤"입니다. 그림의 폭을 보이는 영역 너비에 배율을 곱해 잡고, 높이는 비율대로 따라옵니다. 넘치면 스크롤되고 끌어서 움직일 수 있습니다. 다른 파일을 고르면 배율은 1.0으로 돌아갑니다.

## D14. 오른쪽 클릭 메뉴는 윈도우 것을 그대로 씁니다

우리가 항목을 나열하면 다른 프로그램이 등록한 기능(압축, 소스 관리, 편집기로 열기)이 빠집니다. `IContextMenu`를 호스팅하면 그 전부가 함께 나옵니다.

파일 쪽은 `IShellItemArray.BindToHandler(BHID_SFUIObject)`로, 빈 공간 쪽은 `IShellFolder.CreateViewObject`로 얻습니다.

그림이 들어간 항목과 하위 메뉴는 메뉴가 떠 있는 동안 오는 윈도우 메시지를 `IContextMenu2/3`에게 넘겨 줘야 제대로 그려집니다. 그래서 메뉴가 열려 있는 동안만 창에 갈고리를 겁니다.

## D15. 즐겨찾기는 편집 창에서 직접 고칩니다

메뉴에서 하나씩 빼는 대신 10칸짜리 창을 띄웁니다. 순서를 바꾸거나 여러 개를 한 번에 손보기 쉽습니다.

## D16. 미리보기는 패널별로 켜고 끕니다

전체 메뉴 "미리보기"에 패널 네 개의 체크 항목이 있습니다. 끄면 그 패널의 미리보기 칸이 접히고 목록이 폭을 다 씁니다.
