# 구현 계획

## 1단계 — 뼈대 (완료)

- 솔루션과 세 프로젝트 구성
- 고정 2x2 Grid와 패널 4개
- 설정 모델, JSON 읽기·쓰기, 깨진 파일 복구
- 패널별 시작 위치 읽기와 없는 경로 보정
- 창 위치·크기 저장과 복원
- 마지막으로 클릭한 패널 표시(테두리 강조)

## 2단계 — 파일 패널 (완료)

- 폴더 열거를 백그라운드에서 수행
- `VirtualizingStackPanel` 기반 목록 (파일 1만 개에서 멈추지 않을 것)
- 이동, 뒤로/앞으로, 위로, 주소 표시줄
- 이름·크기·수정일·형식 정렬
- `IShellItemImageFactory` 썸네일 비동기 요청과 LRU 캐시, 폴더 이탈 시 취소
- `FileSystemWatcher` 패널별 감시, 200ms 디바운스

도구 모음은 ← → ↑ · 새 폴더 · 보기 방식 · ⟳ · 검색 순서입니다.
새 폴더 만들기(그 자리 이름 편집, F2)와 보기 방식 전환(자세히/목록/큰 아이콘)은 여기서 함께 넣었고,
검색 단추는 6단계에서 Everything이 붙을 때까지 꺼져 있습니다.

이름 바꾸기는 지금 Directory.Move / File.Move를 씁니다. 6단계에서 IFileOperation으로 바꾸면
되돌리기와 충돌 대화상자가 따라옵니다.

큰 아이콘 보기는 WrapPanel이라 가상화가 되지 않습니다. 파일이 수천 개인 폴더에서는
이 보기만 느려집니다. 자세히·목록 보기는 그대로 가상화됩니다.

2단계에서 남긴 것: 새로고침하면 목록을 통째로 다시 만들기 때문에 선택이 풀립니다.
3단계에서 탭 상태를 다룰 때 선택 유지도 함께 넣습니다.
파일 더블클릭으로 연결 프로그램 열기는 6단계(셸 통합)에서 붙습니다.

## 3단계 — 상단 바 (완료)

- 메뉴는 "패널"과 "탭" 두 갈래입니다. 보기·정렬은 도구 모음과 열 머리글에 이미 있어 메뉴에서 뺐습니다.
  - 패널: 현재 시작 위치 표시, 이 폴더를 시작 위치로, 시작 방식 전환(시작 위치만 / 지난 탭 복원)
  - 탭: 새 탭(Ctrl+T), 탭 닫기(Ctrl+W), 다른 탭 모두 닫기
- 탭 스트립은 `ItemsControl`로 직접 구현했습니다. 기본 `TabControl`은 탭만 떼어 메뉴 옆에 붙일 수 없습니다.
- 탭 전환은 왼쪽 클릭, 닫기는 ✕ 단추나 가운데 클릭입니다.
- 탭이 넘치면 가로로 스크롤합니다. 막대는 숨기고 마우스 휠로 굴립니다. 새 탭 단추는 스크롤 영역 밖이라 항상 보입니다.
- 새로고침·정렬 변경 시 선택이 유지됩니다.
- 탭 구조가 생기면서 뷰모델이 둘로 나뉘었습니다.
  `PaneViewModel`이 탭 목록과 패널 공용 설정(정렬·보기 방식)을 맡고,
  `FileListViewModel`이 탭 하나(폴더·목록·이동 이력)를 맡습니다.

## 4단계 — 설정 화면 (뒤로 미룸)

시작 위치와 시작 방식은 3단계에서 탭바 오른쪽 클릭 메뉴에 들어갔습니다.
남은 항목(썸네일 크기, 숨김 파일, 미리보기 동작, 검색 엔진)은 미리보기를 끝낸 뒤 한 화면으로 묶습니다.

### 원래 계획

- 패널별 시작 위치와 시작 방식을 UI에서 지정
- 미리보기 동작(따라가기 방식, 대기 시간)
- 검색 엔진 선택과 Everything DLL 경로
- 탭 세션 저장·복원

## 5단계 — 미리보기 (이미지·텍스트 완료)

지금 되는 것:

- 이미지 — jpg, png, gif, bmp, tif, ico 등. 가로 1600px를 넘으면 줄여서 디코딩합니다. 작은 그림은 늘리지 않습니다.
- 텍스트·코드 — BOM → UTF-8 → CP949 순으로 인코딩을 가려냅니다. NUL 바이트가 있으면 이진 파일로 보고 거릅니다.
- 그 밖의 형식 — 윈도우 셸에서 1024px 미리보기 그림을 받아 보여 줍니다. PDF·오피스·동영상이 여기에 걸려 대충은 보입니다.

CP949는 .NET Core에 기본으로 없습니다. NuGet 패키지(System.Text.Encoding.CodePages)를 더하는 대신
`MultiByteToWideChar`를 직접 불렀습니다. P/Invoke는 `Explorer.Shell`에만 둡니다.

## 5단계 남은 뷰어

붙이는 순서가 중요합니다. 쉬운 것부터 올려야 미리보기 틀이 일찍 검증됩니다.

1. ~~이미지~~ — 완료
2. ~~텍스트·코드~~ — 완료. 문법 강조(AvalonEdit)는 아직입니다.
3. PDF — WebView2 내장 뷰어
4. 동영상·오디오 — LibVLCSharp (`MediaElement`는 코덱을 시스템에 의존합니다)
5. 오피스 — 셸 미리보기 핸들러(`IPreviewHandler`), 해당 Office가 설치된 경우에만

지원하지 않는 형식은 파일 정보와 "연결 프로그램으로 열기"로 떨어집니다.

셸 핸들러는 WPF 논리 트리 밖에서 그려지므로(에어스페이스 문제) 그 위에 오버레이 UI를 올릴 수 없습니다. 미리보기 위에 버튼을 얹는 설계는 피합니다.

## 6단계 — 셸 통합 (핵심 완료)

지금 되는 것:

- 파일 더블클릭·Enter로 연결 프로그램 열기
- `IFileOperation`으로 복사·이동·삭제. 진행률 창, 같은 이름 충돌 대화상자, 휴지통, Ctrl+Z 되돌리기가 윈도우 쪽에서 따라옵니다
- 클립보드 복사·잘라내기·붙여넣기. 윈도우 탐색기와 같은 규약(FileDrop + Preferred DropEffect)이라 서로 주고받을 수 있습니다
- 다중 선택(Ctrl/Shift 클릭, Ctrl+A)
- 오른쪽 클릭 메뉴는 윈도우 탐색기의 것을 그대로 띄웁니다(`IContextMenu` 호스팅). 파일 위에서 누르면 그 파일들의 메뉴, 빈 자리에서 누르면 폴더의 메뉴가 나옵니다. 다른 프로그램이 등록한 항목도 함께 나옵니다
- 단축키: Enter, Alt+Enter, Backspace, F2, F5, Ctrl+C/X/V, Delete, Shift+Delete
- 속성 창은 윈도우 탐색기의 그것을 그대로 띄웁니다

남은 것:

- 드래그앤드롭 (패널 사이, 그리고 다른 프로그램과)
- Everything 검색

### 원래 계획

- `IFileOperation`으로 복사·이동·삭제·이름 바꾸기
- `IDataObject` 기반 드래그앤드롭 (패널 사이, 그리고 다른 프로그램과)
- `IContextMenu` 우클릭 메뉴
- Everything SDK 검색과 열거 검색 폴백
- 단축키 (F2 이름 바꾸기, F5 새로고침, Ctrl+T 새 탭, Ctrl+W 탭 닫기 등)
- 설정 저장 실패 알림
